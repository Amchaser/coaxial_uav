# 第一阶段工作记录：环境与参数基线

本文件持续记录“环境与参数基线”阶段的实际工作、计算结果、问题和下一步，不替代项目实施计划。

## 2026-07-25：阶段启动

### 已完成

1. 阅读项目需求文档及既有 Gazebo 建模参数报告。
2. 创建项目计划文档：[`项目实施计划.md`](项目实施计划.md)。
3. 核验本机仿真环境：
   - 操作系统：Ubuntu 20.04.6 LTS。
   - 仿真器：Gazebo Garden，`gz-sim7-cli 7.9.0`。
   - 未检测到：ROS 2、`colcon`、Gazebo Classic、Ignition CLI。
   - 当前目录不是有效 Git 仓库；`.git` 目录存在但没有可用 Git 元数据。
4. 建立 `docs/` 与 `config/` 目录。
5. 根据已有模型报告，完成第一版推力余量核算。

### 输入参数

| 参数 | 数值 |
| --- | ---: |
| 机体质量 | 8.2 kg |
| 重力加速度 | 9.8 m/s² |
| 单旋翼推力系数 `kT` | 1.53e-3 N/(rad/s)² |
| 最大角速度 | 167 rad/s |
| 旋翼数量 | 2 |

### 计算结果

| 项目 | 结果 |
| --- | ---: |
| 重量 | 80.360 N |
| 最大总推力 | 85.340 N |
| 悬停转速 | 162.054 rad/s（1547.5 RPM） |
| 推重比 | 1.062 |
| 推力余量 | 6.20% |

### 结论与风险

目前参数组合无法支持可靠的起飞、悬停抗扰与降落缓冲：悬停转速已非常接近最大转速，只剩约 6.2% 推力余量。项目中的“海平面最大单旋翼推力 49.5 N”与 `T=kT×Ω²`、`kT=1.53e-3` 的计算结果不一致，说明推力系数是否已经包含空气密度影响仍需明确。

在解决该问题前，不开始 PID 参数整定。

### 下一步

1. 确定统一的旋翼推力模型：直接使用标定后的 `kT`，或采用显式空气密度的气动模型；两者不可重复叠加空气密度修正。
2. 设定目标推重比不低于 1.5，并反算所需 `kT` 或最大转速。
3. 将确认后的模型、惯量和几何参数写入 `config/` 基线文件。
4. 创建最小 Gazebo 空场景，验证 Garden 7 可正常启动和加载 SDF。

## 2026-07-25：推力目标反算与最小场景

### 已完成

1. 创建初始模型参数文件：[`../config/model_baseline.yaml`](../config/model_baseline.yaml)。
2. 创建最小 Gazebo Garden 世界文件：[`../worlds/baseline_empty.sdf`](../worlds/baseline_empty.sdf)。
3. 以推重比 `T/W = 1.5` 为最低设计门槛，反算两种可选的动力系统标定方向。

### 反算结果

| 条件 | 结果 |
| --- | ---: |
| 目标最大总推力 | 120.540 N |
| 保持最大转速 167 rad/s 时，所需 `kT` | 2.1610671e-3 N/(rad/s)² |
| 保持 `kT=1.53e-3` 时，所需最大转速 | 198.475 rad/s（1895.293 RPM） |

### 说明

以上为达到最低推力余量的工程目标值，不是最终确认的真实旋翼参数。最终值应依据原 Simulink 模型的推力曲线、桨叶/电机数据或独立仿真标定得到。配置文件将其标注为候选反算值，避免被误用为已验证数据。

## 2026-07-25：统一仿真推力模型与场景骨架

### 已完成

1. 将仿真推力模型统一为二次等效模型：`T = kT_sim × omega²`。
2. 采用 `kT_sim = 2.1610671e-3 N/(rad/s)²` 作为**设计基线**；在最大转速 167 rad/s 时，总推力为 120.54 N，对应 `T/W = 1.5`。
3. 明确该等效系数已对应海平面仿真条件，后续实现时不得再次乘以空气密度修正项。
4. 建立 [`../models/coaxial_uav/model.sdf`](../models/coaxial_uav/model.sdf)：包含 8.2 kg 机身、上下共轴旋翼可视盘、双浮筒碰撞体和 IMU。
5. 建立 [`../worlds/static_water_takeoff.sdf`](../worlds/static_water_takeoff.sdf)：包含物理系统、传感器系统、静水视觉/接触平面与无人机实例。
6. 建立 [`../scripts/run_static_water.sh`](../scripts/run_static_water.sh) 作为标准场景启动入口。

### 设计说明

- 本阶段浮筒只提供接触与防侧翻几何，尚未启用浮力或水动力插件；这符合项目“不开展流体力学建模”的范围。
- 上下旋翼目前是固定的可视化链接，尚未接入电机插件或控制分配器。下一步将增加可控旋转关节、原生电机插件与状态发布。
- 等效推力系数是保证控制开发有足够推力余量的仿真参数，不应被写入最终实体机参数表。

### 启动验证备注

首次调用启动脚本时，服务器参数没有被转发，Gazebo 因而尝试启动 GUI；当前执行环境不支持 OpenGL 3.3，GUI 不可用。已修正脚本，使 `scripts/run_static_water.sh -s` 显式请求纯服务器模式；随后需以该模式复测模型加载。

## 2026-07-25：双旋翼动力接口

### 已完成

1. 将上下旋翼由固定链接改为绕 Z 轴的连续转动关节。
2. 在静水场景中为上、下旋翼分别接入 Gazebo Garden 原生 `MulticopterMotorModel`。
3. 电机模型采用阶段 1 的等效标定系数 `2.1610671e-3 N/(rad/s)²`、最大转速 167 rad/s 和 0.075 s 一阶响应时间常数。
4. 上旋翼设为 CW、下旋翼设为 CCW；力矩常数按 `kQ/kT ≈ 0.06478` 设置，以保留反扭矩平衡关系。

### 当前接口

设计的命令接口为 `/coaxial_uav/gazebo/command/motor_speed`，消息类型为 `gz.msgs.Actuators`；其中 `velocity[0]` 为上旋翼转速、`velocity[1]` 为下旋翼转速，单位为 rad/s。控制器与起飞状态机将在这一接口之上实现。

### 验证问题与修正

首次服务器加载时，原生电机插件在更新阶段段错误。该版本 Garden 的插件需要模型内局部关节/链接名，不能直接使用本项目模型的全限定名称。已改为 `upper_rotor_joint`、`lower_rotor_joint` 等局部名称，并显式提供旋翼阻力及滚转力矩系数；需要重新进行服务器加载验证。

复测结果：修正后的含电机静水场景在纯服务器模式下连续运行 8 秒，未出现 SDF、URI、插件或运行时错误。下一项验证为发布两路转速命令并读取电机状态主题。

### 当前验证边界
